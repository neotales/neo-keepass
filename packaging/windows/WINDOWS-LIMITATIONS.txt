nkp (neo-keepass) for Windows — platform limitations
====================================================

PRIVATE FILE WRITES ARE SUPPORTED WHEN WINDOWS SECURITY CHECKS SUCCEED.
nkp fails closed when it cannot establish and verify the required protection.

On Windows, nkp creates private files with a protected DACL granting access
to the current user, and verifies the resulting security descriptor before
writing. The volume must advertise persistent ACL enforcement. Unsupported
or unqueryable volumes, or any failed security verification, are rejected
before file contents are written. This applies to vault creation/mutation,
configuration files, and CLI output files.

The implementation uses path-based staging and assumes the containing
directory is trusted and not controlled by an adversary. It does not defend
against administrators or the same user. These guarantees have not been
established for every filesystem, elevated execution, or every Windows
account/configuration; do not infer broader coverage from this notice.

This is not a claim of Unix permission parity. On Unix, nkp uses mode 0600;
Windows uses ACLs and the platform's security APIs. Reading existing vaults
and printing to stdout are supported independently of private-file writes.
Do not loosen directory ACLs or bypass a failed security check: failure is
intentional protection, not an indication that an unprotected write is safe.
