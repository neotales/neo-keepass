# Milestone `v0.0.0-alpha.0`

**Release tag:** `v0.0.0-alpha.0`
**Target date:** 2026-11-24
**Scope:** Initial tagged alpha release of `neo-keepass` (`nkp` CLI/TUI and experimental `nkpui` Rune desktop UI).

## Milestone goals

Deliver a cohesive, security-hardened, cross-platform alpha covering headless KeePass vault management, `nkp://` secret template and `.env` injection, directory-scoped shell integration, verified live `keepassxc-cli` interoperability, core desktop CRUD in `nkpui`, and a reproducible 6-target release pipeline.

## Verified completion checklist

### CLI ergonomics, help, completions, and output safety (`nkp`)
- [x] **P0/P1/P2 CLI hardening and keyboard-friendly routing:** Unified token parsing, strict option allowlists, fail-closed global `-V`/`--vault` placement, root shortcuts (`use`, `ls`/`list`, `search`, `show`, `get`, `get many`, `set`, `rm`/`remove`, `ensure`, `otp`, `env`, `import`, `export`, `sync`, `inject`, `trust`, `untrust`, `shell`, `exec`/`x`, `completion`), and deterministic `NEO_KEEPASS_*` → `NKP_*` environment variable precedence.
- [x] **Unified docopt-style help:** Standardized 88-column help output across root and nested routes, aligned with [the documentation index](../README.md) and [command alias index](../commands.md).
- [x] **6-shell completions:** Static and dynamic vault-aware completions (`nkp completion SHELL`, `nkp shell completions SHELL`, private `nkp __complete`) for `bash`, `sh` (POSIX), `zsh`, `fish`, `powershell`/`pwsh`, and `nushell`.
- [x] **`--format human` and output safety:** Human-readable `--format human` rendering on metadata routes, `--color`/`--no-color` control, and unified broken-pipe (`EPIPE`) handling across stdout and stderr sinks without panics.

### Secret injection (`nkp://`) and `.env` resolution
- [x] **`nkp://` URI parser and single-pass template engine:** Supports `nkp://[@vault/]entry[#field|#otp]` with `%HH` percent-encoding and non-recursive single-pass substitution via `nkp inject`.
- [x] **Child-process `.env` injection:** `nkp exec --env-file` (`nkp x --env-file`) resolves `KEY=nkp://...` bindings into child process environments without writing plaintext secrets to disk.

### Directory-scoped shell integration (`nkp shell` & `nkp trust`)
- [x] **`.nkp.toml` project manifests:** Schema `version = 1` supporting vault selection, `[env]` bindings, `env_file`/`env_files`, and bounded `inherit = "stop" | "merge"` directory traversal.
- [x] **Fail-closed trust store and revert engine:** Explicit `nkp trust`, `nkp untrust`, and `nkp trust list` gating before loading `.nkp.toml`, with automatic environment diffing and revert on directory exit via `nkp shell init|load|unload|status` and `nkp __hook` for `bash`, `zsh`, `fish`, `powershell`/`pwsh`, and `nushell`.

### Interoperability (`keepassxc-cli 2.8.0`)
- [x] **Live KeePassXC interop suite:** Verified round-trip compatibility against `keepassxc-cli 2.8.0` via `neotales-keepass` (`cli_interop`) and `nkeepass` (`keepassxc_interop`), backed by a dedicated CI `keepassxc-interop` lane.

### Rune desktop application (`nkpui`)
- [x] **Isolated Rune workspace (`crates/nkpui`):** Built on pinned `anomalyco/rune` (`rev = 761fd132a286b9e87756d8a0889c8957b93c86be`) with `#![forbid(unsafe_code)]` and `tooling` excluded from release builds.
- [x] **Core vault and entry workflows:** Create/open `.kdbx` vaults (password and/or key file), group and entry CRUD, tags, custom fields, binary attachments (attach, extract, remove), password generation, TOTP display, search and breadcrumb navigation, dirty-vault save/discard confirmation before locking, idle and focus-loss auto-lock, and timed clipboard lease clearing.

### Security and UI audits
- [x] **CLI/service hardening:** Symlink-safe bounded file opens (`fs_safe`), BiDi and Unicode line-separator rejection across service metadata and CLI inputs, `Zeroizing` secret buffers, hardened `shell load` option parsing, signal-safe terminal mode restoration in the TUI, and verified current-user DACL enforcement on Windows.
- [x] **`nkpui` security and UI polish:** Focus-loss lock and transient widget wiping during unlock, bounded nofollow attachment reads, preallocation caps, vault creation password-mismatch validation, keyboard activation, pinned editor header, tag icon, custom field labels, and detail/sidebar layout fixes.

### Release engineering and CI/CD
- [x] **6-target release workflow (`.github/workflows/release.yml`):** Locked builds, architecture verification, packaging, `SHA256SUMS` generation, and tag-gated GitHub Release publishing for `linux-amd64`, `linux-arm64`, `macos-amd64`, `macos-arm64`, `windows-amd64`, and `windows-arm64` (`nkp` + `nkpui`).
- [x] **Supply-chain pinning:** All 54 `uses:` action references across `.github/workflows/` pinned to verified 40-character commit SHAs, with `scripts/check-workflows.sh` guarding workflow shell blocks.

## Next milestone: `v0.0.0-alpha.1` (Longer Pass)

The following capabilities were deliberately deferred from `v0.0.0-alpha.0` to keep the initial release focused and auditable:

- **OTP editing & provisioning in `nkpui`:** Interactive `otpauth://` URI/seed creation, editing, and provisioning UI (currently `nkpui` renders TOTP codes read-only; CLI supports `nkp otp` and `nkp set --field otp=...`).
- **Import / export UI in `nkpui`:** Graphical import, export, and sync flows (currently CLI-only via `nkp import`, `nkp export`, and `nkp sync`).
- **Database-level settings UI in `nkpui`:** Vault KDF parameters, cipher selection, metadata editing, and master credential rotation inside the desktop UI.
- **Phase 2 `nkp unlock` / `nkp lock` volatile session agent:** Ephemeral in-memory/local-socket session daemon so repeated CLI invocations can reuse an unlocked session without re-entering master credentials.
- **Extended integrations:** Passkeys, Have I Been Pwned (HIBP) breach checks, SSH-agent integration, and automatic age/SSH recipient discovery.
